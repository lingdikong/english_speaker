## 修复收起手势闪烁（PlayerView.swift + RootView.swift）

用户反馈：慢慢下滑再慢慢上滑时页面闪烁。三个叠加原因，全部修掉：

1. **主因：手势坐标系自反馈**。dismissDrag 挂在 header 上，header 处于被 scaleEffect+offset 变换的容器内，DragGesture 默认 `.local` 坐标系——手指位移被当前缩放值放大（translation = 屏幕位移 / scale）。于是「位移↑→collapse↑→scale↓→位移↑」正反馈，且映射 d = 340c - 217.6c² 在 c>0.781 后非单调（同一手指位置对应两个解），慢拖时进度在解之间跳 → 闪烁。修复：`DragGesture(minimumDistance: 10, coordinateSpace: .global)`，位移取屏幕坐标，不受自身变换影响，反馈闭环断开。
2. **位移公式二次化**：原 `offset = (targetY - h/2) * collapse`，而 targetY 内含 scale（也含 collapse），进度被算两次 → (270c-156)*c，c<0.577 时 dy 为负（卡片先往上跑再往下），方向反转像跳一下。修复：改为**锚定卡片「左边+底边」**插值：dx = dockLeft*c - (w - w*s)/2，dy = (h - h*s)/2 - dockBottom*c → 对进度严格线性（dy = 114c），全程单调向下。落点校验：底边=844-156=688、左边=16 ✓。
3. **拖动中 header 的 allowsHitTesting 被 chrome>0.2 反复开关**，可能打断手势触发意外 onEnded（弹回→闪）。改为只看 `!focus && !dismissing`。

另修：collapseToMini() 里 `dismissing = true` 原先写在 withAnimation 之外 → cardOpacity 瞬间跳 0、页面「啪」地消失而非边缩边淡出；已移入同一动画块。
性能：RootView 的底层缩放只作用于当前 Tab（`t == ui.tab ? 0.94 + 0.06*playerCollapse : 1`），隐藏的 3 个 Tab 不再每帧参与变换。

经验：给「视图自身被变换」的图层挂 DragGesture，必须用 .global（或 .named 挂在未变换容器上），否则必然自反馈。

## 修复文章读完/合成终止后无声空转（全平台，core 层）

用户反馈：文章读完且待播清单为空时，播放器仍显示播放中但没有声音，应该停止。三端 UI（web store.applyPlayer、Apple Store.handle、Android SpeakerRepository.onPlayerState）对 ended→advance 空清单的处理本就正确，根因在共享 core 的状态机有两个"永远不停止"的洞：

1. **结尾判定依赖 `played_frames() >= written` 精确对齐**（player.rs pump）：平台 sink 帧数统计若差一点永远追不上（舍入/内部缓冲/变速切换后 played=consumed·src/dev·rate 只按当前倍速换算），播放器卡在 Playing 无声空转。修复：end_stream 只调一次（end_flushed 标记），冲尾后记录 played_frames 最近前进时刻 last_advance，超过 END_STALL=500ms 不再前进即强制进入 Ended（换 song/seek 时重置标记）。
2. **合成任务终止后永远 Buffering**：边听边转追上合成进度 → Buffering；合成失败/被取消（任务不再续转）时 worker 只发 DataAvailable，播放器永远缓冲。修复：新增 `PlayerCmd::SynthDone(id)`，worker 在任务真正终止（Failed / Stopped 且未 requeued）时发送；player 收到后置 synth_done 标记，pump 在数据前沿把 Playing/Buffering 转为 Paused（pause+save_progress），DataAvailable 会清除标记。

验证：es-core 15 测试 + es-runtime 6 测试（新增回归 `stop_when_synthesis_ends_before_audio_does`：边听边转→Buffering→cancel_synthesis→应 Paused）全过；es-desktop 新增 `played_frames_reaches_written_at_end_of_stream`（模拟 WSOLA→重采样→声卡消费全程，4 档倍速下 played 最终追上 written）通过。注意该测试在 debug 下因 WSOLA best_offset 全搜索很慢（1 秒音频≈140s），勿随意加长音频长度。

## 展开跳动 + 下拉过快（PlayerView.swift）

1. **展开到全屏时跳一下**：根因是弹簧欠阻尼。expand() 用 `.spring(response: 0.42, dampingFraction: 0.88)` 把 collapse 1→0，收尾会冲过 0 → 负进度 → morph 算出「比屏幕还宽的窗口 + 负圆角」→ 跳一下。两处修复：① morph 里 `let c = min(1, max(0, collapse))` 夹住（取消收起的 spring 0.86 同样会冲过 0）；② 展开/回弹弹簧都改成 dampingFraction: 1（临界阻尼，不冲过）。
2. **下拉移动太快**：原尺寸与位置都按进度线性插值 → 手指走 340pt 时卡片顶边要跑 766pt（2.25 倍）→ 感觉飞出去。修复：dismissDistance 340 → 460；尺寸用二次曲线 `sp = c*c`（开头几乎只跟手下移，末段才快速收成球），位置仍线性。实测（852 高屏）：手指 100pt → 顶边 99pt（≈1:1），手指 200pt → 236pt（1.18x），终点 766pt（1.67x）。松手阈值同步放宽到 collapse > 0.3 或 predictedEnd > 320。

经验：这类「进度 → 几何」映射凡是带弹簧的，都必须把进度 clamp 到 [0,1]，否则负进度会让尺寸/圆角越界；另外「位移+缩放」同时线性会在视觉上放大到 2 倍以上手指速度，缩放必须用更慢的曲线。

## 播放页不满屏 + 小球落点偏移（PlayerView.swift）——坐标系根因

用户反馈：player 背景没铺满全屏；小球落点不对。根因是**坐标系用错**：把 GeometryReader 直接放在页面里，读到的是「安全区盒子」（比屏幕矮 状态栏 + home 条，本例 771 而非 852，且 safeAreaInsets 为 0）。之前页面靠 `p.bg.ignoresSafeArea()` 把背景撑出安全区所以看不出来；改成取景窗 + clipShape 后，超出安全区的背景被裁掉 → 上下露出底层界面（不满屏）；同时落点公式 `h - bottom - 30` 里的 h 少了 34pt → 小球偏高一个 bottom inset。

修复：新增 `FullScreen<Content>` 容器（`GeometryReader { content($0) }.ignoresSafeArea()`），内层读到的就是**整屏**尺寸、原点在屏幕顶部。外层仍保留一个 probe GeometryReader，只用 `probe.frame(in: .global).minY` 与 `probe.safeAreaInsets.top` 换算 contentTop（header 距屏幕顶）与 fadeTop（原文顶部渐隐高度），从而保证两种假设下 header 位置都与改动前一致。page() 签名从 `geo: GeometryProxy` 改为 `contentTop/fadeTop: CGFloat`。

落点公式校验（BottomBar 自身只忽略底部安全区，药丸是按「距屏幕底 26」定位的）：无论根容器是全屏还是安全区盒子，药丸在窗口坐标里的 y 都是 796（852-26-30）；我的公式 `h_screen - bottom - 30` 与之一致 ✓。x：A→46、B→116、C→w-46 ✓。

教训：凡要按「屏幕」而不是「安全区」计算几何，必须先 ignoresSafeArea 再测量；直接用页面里的 GeometryReader 读到的是安全区盒子。

## 停止播放后灵动岛指示器常驻 / 锁屏显示仍在播放（AudioSink.swift / NowPlayingCenter.swift / Store.swift）

用户反馈：停止播放、退到后台后，灵动岛一直占着，锁屏发现还在播放。

根因两条，都不在 UI 层：

1. **AVAudioSession 只 activate 从不 deactivate**。`AudioSessionController.activate()` 只 `setActive(true)`，全工程没有任何 `setActive(false)`；且 `Info.plist` 有 `UIBackgroundModes=audio`。会话永久 active → iOS 一直把 App 当作「正在播放音频的 App」：灵动岛播放指示器常驻、后台不挂起、锁屏媒体控件不下线。雪上加霜的是 `EngineAudioSink.pause()` 只 `player.pause()`，AVAudioEngine 从不 stop，仍在渲染静音，硬件 I/O 一直占着（也导致 deactivate 会失败）。

2. **MPNowPlayingInfoCenter 状态不准且不清空**。`update()` 里 `playbackState = isPlaying ? .playing : .paused`，`nowPlayingInfo` 只要还有 `store.current` 就一直保留；`.stopped` 分支只在「没有当前文章」时走到，暂停时永远走不到。

修复：
- `AudioSessionController` 加 `active` 标志与 `deactivate()`（`setActive(false, options: .notifyOthersOnDeactivation)`），activate 幂等。
- `EngineAudioSink` 新增 `suspend()`：记录当前采样位置 → player.pause → engine.stop → 会话停用。`resume()` 里先 activate，engine 不在跑时 start 并做**时间轴 rebase**（新增 `timeOffset`，引擎重启后 player 时间轴归零，`currentSampleTimeLocked()` 返回 `t.sampleTime + timeOffset`，避免 playedFrames 倒退/进度卡死；`resetLocked()` 清零）。`closeOutput()` 也补 engine.stop + deactivate。
- `NowPlayingCenter` 新增 `clear()`（info=nil + playbackState=.stopped + 清 artwork）；`update()` 在 `.ended`/`.idle` 时 clear，其余按 status 精确映射 playing/buffering→.playing、paused→.paused。
- `Store` 新增 `syncAudioSession(for:)`，在 `playerStateChanged` 分支调用：playing/buffering→activate，paused→deactivate + sink.suspend。`play`/`resume`/`togglePlay`/`playSpan` 显式 activate（锁屏点播放时会话可能已停用）。ended 分支延迟 600ms 确认仍 ended 再释放（避免打断 advanceQueue 自动连播）。

注意：不要在暂停时调 `flush()`（会 resetLocked 把 playedFrames 归零，核心层 base_frame 没跟着重置 → 进度错乱），suspend 走的是保存/恢复时间轴的路子。

验证：swiftc -parse 三个文件通过；完整 typecheck 仍被 @Observable 宏插件阻塞（环境问题），需 Xcode ⌘B 确认。真机验证点：暂停→灵动岛指示器消失；播放中退后台→仍后台播放；锁屏点暂停→指示器消失；恢复播放→进度连续不跳。

## 点暂停后图标“慢一下”（Store.swift）

PlayGlyph 是纯 `if playing` 切换、PressStyle 只有 0.15s 透明度动画，所以延迟不在 UI 层，两个来源：

1. **上一轮自己引入的主线程阻塞**：`syncAudioSession` 在 paused 时于主线程同步执行 `AudioSessionController.deactivate()` + `engine.stop()`。停用会话要等硬件释放、拆渲染链要停引擎，合计可达上百毫秒 → UI 卡住 → 点完暂停图标慢一拍才变。修复：`let sink = self.sink; DispatchQueue.global(qos: .userInitiated).async { sink.suspend() }`（suspend 内部已含 deactivate）。ended 分支的延迟释放同样移到 `qos: .utility` 后台队列。
2. **核心异步往返**：`core.pause()` 是「命令投递 → player 线程处理 → 事件回调主线程」，图标要等状态事件回来才变。修复：乐观更新——`pause()` 里 `if isPlaying { player.status = .paused }`；`resume()`/togglePlay/play/playArticle 里 `player.status = .buffering`（.buffering 也算 isPlaying，图标会显示暂停态）。真实状态事件回来后覆盖，不会错。

经验：任何 `AVAudioSession.setActive` / `AVAudioEngine.start|stop` 都不要放在 MainActor 上；而「核心异步状态」驱动的 UI 开关，都应该在本地先乐观更新。

验证：swiftc -parse 三文件通过；仍需 Xcode ⌘B + 真机确认手感。

## Android 端与 iOS 行为对齐检查（platforms/android）

用户要求检查 Android 行为与 iOS 一致。逐项比对最近在 iOS 上迭代过的行为：

**已一致、无需改动：**
- 逐词高亮不重排：Android `SentenceText.kt` 用 `drawBehind` + `rangeRects` 画胶囊，纯绘制、不占布局（iOS 是从 padding 改成 background 才做到的）。弱读词 0.84em 也不随高亮变化 → 无位移。
